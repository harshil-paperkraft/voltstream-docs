# Voltstream documentation

Public documentation for Voltstream — event delivery infrastructure.
Built with [Docusaurus](https://docusaurus.io/) and deployed to
`docs.voltstream.io`.

> **Sample content.** Voltstream is a fictional company. This repository exists
> as a realistic documentation estate for testing documentation tooling.

## Structure

```
docs/
  intro.md              Introduction
  getting-started/      Quickstart, installation, authentication
  guides/               Delivery, idempotency, filtering, rate limits, replay
  tutorials/            End-to-end walkthroughs
  api/                  Reference: overview, streams, events, endpoints, errors
  faq.md                Frequently asked questions
blog/                   Changelog — one post per release
```

The sidebar is **autogenerated** from the folder structure. Ordering and labels
come from each folder's `_category_.json`, so adding a page never means editing
`sidebars.js`.

## Develop

```bash
npm install
npm start          # http://localhost:3000, hot reload
npm run build      # production build; fails on broken links
npm run serve      # serve the production build locally
```

`onBrokenLinks` is set to `throw`, so a broken internal link fails the build
rather than shipping.

## Contributing

- One page per concept. If a page needs two `<h1>`-level ideas, it is two pages.
- Every code sample must run as written. No pseudo-code, no `...` standing in
  for a required parameter.
- Prefer counts to adjectives — "retries 8 times over 24 hours", not "retries
  several times".
- Document the failure case. Most support tickets are about what happens when
  something goes wrong, not when it works.
